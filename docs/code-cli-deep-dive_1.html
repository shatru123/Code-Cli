01 · Overview

What is Code-Cli?

Code-Cli is a terminal-native AI coding assistant written in pure C# 12 / .NET 8. It communicates with Ollama — a local LLM runtime — via HTTP streaming, giving you a private, fast AI pair programmer that runs entirely on your own hardware.

It ships as a single self-contained executable (no .NET runtime install required on target), supports both local Ollama and Docker Ollama runtimes, and has zero NuGet package dependencies. Every feature is built on the .NET Base Class Library alone.

Core mechanism in one sentence: Code-Cli sends a crafted system-prompt + user input as an HTTP POST to http://localhost:11434/api/generate and streams the NDJSON response token-by-token to your terminal.

Program.cs — Line by Line

The entire entry point in 287 lines of C# 9+ top-level statements. No class wrapper. No explicit Main() method. The compiler generates this automatically.

📄 Program.cs

1–3 using CodeCli.Commands; using CodeCli.Services; using CodeCli.UI; Import all three internal namespaces. Zero NuGet — these are all local classes in src/. No System.CommandLine, no Newtonsoft.Json, nothing external.
5–12 using var cts = new CancellationTokenSource(); Console.CancelKeyPress += (_, e) => { e.Cancel = true; cts.Cancel(); ConsoleUI.Warning("Cancelled."); }; e.Cancel = true prevents the OS from hard-killing the process. Instead it signals the token, letting all async operations observe cancellation and clean up. using var disposes the source when program exits.
14–19 string? modelOverride = GetFlag(args, "--model"); string? hostOverride = GetFlag(args, "--host"); string? outputFile = GetFlag(args, "--output"); string? runtimeOverride= GetFlag(args, "--runtime"); bool noStream = args.Contains("--no-stream"); bool verbose = args.Contains("--verbose"); Parse global flags BEFORE routing so they're available to all commands. Flags with values use GetFlag(); boolean flags use simple Array.Contains(). All nullable strings — compiler enforces null checks downstream.
21 var cleanArgs = StripFlags(args); Remove all --flag value pairs from the array. What remains is positional: ["fix", "MyService.cs"]. Without this, args[0] could be a flag name rather than the command verb.
23–30 var config = ConfigManager.Load(); if (modelOverride is not null) config.Model = modelOverride; if (hostOverride is not null) config.Host = hostOverride; if (noStream) config.Stream = false; Load ~/.code-cli/config.json first (auto-creates on first run with defaults), then overlay CLI flags on top. CLI always wins. Uses C# 9 is not null pattern for clarity over != null.
32–37 if (cleanArgs.Length == 0) { ConsoleUI.PrintHelp(); return 0; } Guard clause: no arguments = show help and exit clean. return 0 in top-level statements = process exit code 0. Simple and user-friendly.
39–40 var command = cleanArgs[0].ToLowerInvariant(); var runtime = new OllamaRuntimeManager(config); Lowercase the command for case-insensitive matching. Instantiate the runtime manager early — it reads config.Runtime to know whether we're in local or Docker mode.
42–68 if (command is "--help" or "-h" or "help") { ConsoleUI.PrintHelp(); return 0; } if (command is "--version" or "-v") { Console.WriteLine("Code-Cli v1.0.0"); return 0; } if (command is "config") { ConfigManager.Print(config); return 0; } "No-Ollama" commands short-circuit here before any HTTP calls. Uses C# 9 pattern matching: is "a" or "b" or "c" — cleaner than multiple || conditions.
70–72 var ollama = new OllamaService(config.Host); var assistant = new CodeAssistantService(ollama, config.Model); Construct the two core service objects. OllamaService owns the HttpClient. CodeAssistantService wraps it with AI-specific prompt logic. Both are constructed once and shared across all command handlers.
74–100 if (runtime.UsesDocker) { var prep = await ConsoleUI.WithSpinnerAsync( "Preparing Docker runtime", () => runtime.PrepareAsync(cts.Token), cts.Token); if (!prep.Success) { ... return 1; } } Docker mode only: shows animated spinner while attempting to start/connect to the Ollama container. PrepareAsync() runs docker run or docker start. On failure, prints per-step recovery instructions.
102–125 if (command is "models") { var models = await ConsoleUI.WithSpinnerAsync( ..., () => ollama.GetAvailableModelsAsync(), ...); ConsoleUI.PrintModelTable(models); return 0; } Special case for models: handled before the general health check since it is the health check. Calls Ollama's list endpoint, renders a table. Suggests install command (runtime-aware: local vs docker).
127–145 bool ollamaRunning = await ConsoleUI.WithSpinnerAsync( "Connecting to Ollama", () => ollama.IsRunningAsync(), cts.Token); if (!ollamaRunning) { ConsoleUI.Error(...); foreach (var step in runtime.GetStartupHelp()) Console.WriteLine($" {step}"); return 1; } Health check with spinner. IsRunningAsync() does a lightweight GET to Ollama. GetStartupHelp() returns different steps depending on runtime (local: "ollama serve" vs docker: "docker start code-cli-ollama").
147–240 switch (command) { case "chat": await new ChatCommand(assistant).ExecuteAsync(cts.Token); break; case "ask": question = string.Join(" ", cleanArgs[1..]); await new AskCommand(assistant).ExecuteAsync(question, outputFile, cts.Token); break; case "write": ... case "fix": await new FixCommand(assistant).ExecuteAsync( cleanArgs[1], GetFlag(args,"--error"), outputFile, cts.Token); break; case "review": ... case "explain": ... default: ConsoleUI.Error($"Unknown command: '{command}'"); exitCode = 1; } Main routing switch. Each case: (1) validates required args are present, (2) constructs the command object, (3) awaits ExecuteAsync with relevant inputs + CancellationToken. The cleanArgs[1..] range syntax (C# 8) slices the array.
242–258 catch (OperationCanceledException) { ConsoleUI.Warning("Cancelled."); exitCode = 130; } catch (Exception ex) { ConsoleUI.Error($"Unexpected: {ex.Message}"); if (verbose) Console.WriteLine(ex.StackTrace); exitCode = 1; } Global exception handlers wrap the entire switch. Exit code 130 is the POSIX standard for Ctrl+C. Stack trace gated behind --verbose — normal users don't want noise, debuggers do.
263–287 static string? GetFlag(string[] args, string flag) { var idx = Array.IndexOf(args, flag); return idx >= 0 && idx + 1 < args.Length ? args[idx + 1] : null; } static string[] StripFlags(string[] args) { var result = new List<string>(); var flagsWithValues = new HashSet<string> { "--model", "--host", "--output", "--error", "--runtime" }; for (int i = 0; i < args.Length; i++) { if (flagsWithValues.Contains(args[i])) { i++; continue; } if (args[i].StartsWith("--")) continue; result.Add(args[i]); } return result.ToArray(); } Two local helper functions. GetFlag: linear search + next-element return (O(n), fine for tiny arg arrays). StripFlags: uses a HashSet for O(1) flag lookup. Skips both the flag key AND its value (i++). Drops boolean flags (--verbose etc). Returns only positional args.
08 · Services

Service Layer — src/Services/

Four service classes form the backbone of the application. Each has a single responsibility and communicates through clean interfaces.

Service Interaction Diagram
OllamaService — The HTTP Layer
Owns one HttpClient (singleton pattern). For streaming, uses HttpCompletionOption.ResponseHeadersRead to begin reading before the full response arrives. Reads response line-by-line (ReadLineAsync()), parses the "response" field from each NDJSON object using basic string parsing (no JSON library), and yields each token via IAsyncEnumerable<string>.
CodeAssistantService — The Prompt Engineer
One method per command type. Each method builds a different expert system prompt. For example, FixBugsAsync() uses a prompt like "You are an expert C# bug fixer. Analyze this code thoroughly, identify ALL bugs, return the complete fixed code with comments explaining each fix." The prompt quality is the single most impactful factor on output quality.
ConfigManager — The Persistence Layer
Uses System.Text.Json (built into .NET 8) for reading and writing. The config path is Path.Combine(Environment.GetFolderPath(Environment.SpecialFolder.UserProfile), ".code-cli", "config.json"). Creates the directory and file with defaults if either doesn't exist.
OllamaRuntimeManager — The Environment Manager
Decides between local and Docker mode based on config.Runtime. In Docker mode, PrepareAsync() calls Docker CLI commands via Process.Start(): first tries docker start code-cli-ollama, and if the container doesn't exist, runs the full docker run -d --name code-cli-ollama -p 11434:11434 -v code-cli-ollama:/root/.ollama ollama/ollama:latest.
09 · Commands Detail

All Commands — Detailed Reference

Chat Command — Special REPL Flow
chat
Infinite REPL loop. Full conversation history (list of {role, content} pairs). Supports inline /fix, /review, /explain, /model, clear, exit. History trimmed to history_size config value. Ctrl+C exits gracefully.
code-cli chat code-cli chat --model deepseek-coder:6.7b code-cli chat --runtime docker
ask
Single-turn Q&A. Joins cleanArgs[1..] with spaces so quotes aren't required. Streams answer. Expert coding assistant system prompt — focused on C#/.NET by preferred_language setting.
code-cli ask How does IQueryable differ from IEnumerable code-cli ask "CQRS in .NET 8" --output ans.md
write
Code generation from a plain-English description. System prompt instructs: production-ready code, proper error handling, XML doc comments, follow SOLID principles. Streams generated code.
code-cli write "JWT auth middleware ASP.NET Core 8" code-cli write "Thread-safe LRU cache C#" --output LRU.cs
fix
Reads file via File.ReadAllTextAsync(). Sends full source code + optional error context. System prompt: "identify ALL bugs, return the complete fixed code." Optional --error makes the fix targeted.
code-cli fix Program.cs code-cli fix MyService.cs --error "NRE at line 42" code-cli fix f.cs --output f.fixed.cs
review
Full production-readiness audit. System prompt covers: security vulnerabilities, SOLID principles, performance issues, error handling gaps, logging, test coverage. Returns structured markdown report.
code-cli review AuthController.cs code-cli review PaymentService.cs --output review.md
explain
Line-by-line walkthrough. System prompt instructs: explain purpose, patterns used, key design decisions, trade-offs, potential improvements. Great for onboarding or understanding unfamiliar code.
code-cli explain Program.cs code-cli explain Algorithms/QuickSort.cs --output exp.md
models
Lists installed Ollama models via GET /api/tags. Renders table with name, size. Shows active model. Suggests pull command (runtime-aware: docker exec vs ollama pull).
code-cli models
config
Prints the current AppConfig loaded from ~/.code-cli/config.json. Read-only from CLI — edit the JSON file to change settings permanently. Created on first run with sensible defaults.
code-cli config code-cli --version code-cli --help

install.bat — Windows Auto-Install

📦 install.bat
61 lines · Windows Batch · User-scope PATH patch
11–13 set INSTALL_DIR=%USERPROFILE%\.code-cli\bin set EXE_NAME=code-cli.exe set SOURCE_EXE=publish\%EXE_NAME% Install target is ~/.code-cli/bin/ — inside user home directory, no admin rights needed. Same pattern as npm, rustup, go.
33–44 for /f "tokens=2*" %%A in ( 'reg query "HKCU\Environment" /v PATH' ) do set CURRENT_PATH=%%B echo %CURRENT_PATH% | findstr /i "%INSTALL_DIR%" if %ERRORLEVEL% neq 0 setx PATH "%CURRENT_PATH%;%INSTALL_DIR%" Reads user PATH from Windows Registry (HKCU\Environment), checks if install dir is already present using findstr. If not, uses setx to permanently write the new PATH to the registry. No admin — HKCU is user-scoped.
